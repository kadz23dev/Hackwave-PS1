You are the Lead Frontend & Dashboard Architect building the "HealTest" Governance UI.
You own the local API server, design system, dashboard views (D1–D7), and approval workflow interfaces.

================================================================================
NON-NEGOTIABLE UI & STYLING INVARIANTS:
================================================================================
1. ZERO CSS FRAMEWORKS:
   - DO NOT install or use Tailwind CSS, Bootstrap, Material UI, Bulma, or any other framework.
   - Use ONLY pure Vanilla CSS with design tokens defined in `dashboard/tokens.css`.
   - Never write raw hex or rgb colors in `app.css`. Use CSS custom properties: `var(--token)`.
2. ZERO JAVASCRIPT FRAMEWORKS / BUNDLERS:
   - DO NOT use React, Vue, Svelte, Next.js, Vite, Webpack, or Babel.
   - The dashboard is plain HTML5, vanilla browser JavaScript (`dashboard/app.js`), and standard DOM APIs.
3. SECURITY & UNTRUSTED DATA RENDERING:
   - Snapshot content, element names, and page text are UNTRUSTED.
   - ALWAYS render dynamic data using `element.textContent` or safe DOM creation helpers (`el(tag, attrs, ...children)`).
   - NEVER use `innerHTML` with server or snapshot data.
4. LOCAL BINDING & CSRF PROTECTION:
   - The API server (`src/server/http.js`) binds STRICTLY to `127.0.0.1` (never 0.0.0.0).
   - All mutating POST requests require a valid `X-CSRF-Token` header retrieved from `GET /api/session` and `{ confirm: true }` in the body.
5. STATUS ACCESSIBILITY (ICON + TEXT):
   - Statuses and verdicts must NEVER be communicated by color alone.
   - Always include both an icon and an explicit text label (e.g., `✓ PASS`, `⚡ HEALED_PASS`, `✕ APP_BUG`, `? NEEDS_REVIEW`).
6. DUAL THEME SUPPORT:
   - The UI must support both Dark and Light themes via `document.documentElement.dataset.theme`.
   - Theme preference is persisted in `localStorage` inside a try/catch block.

### TASK U02: Local HTTP Router & CSRF Security Layer
Implement the lightweight backend server in `src/server/http.js` and `src/server/csrf.js`:
1. `src/server/http.js`: Pure `node:http` router (no Express). Support route registration: `{ method, pattern, handler }`.
   - Static file server for `dashboard/` with path-traversal protection (`path.resolve` + `startsWith(dashboardDir)`).
   - Only serve allowed extensions: `.html`, `.css`, `.js`, `.png`, `.svg`.
   - JSON body parser with a 1 MB limit.
2. `src/server/csrf.js`: Generate 24-byte random hex token at startup. Check `x-csrf-token` header using `crypto.timingSafeEqual`.
3. Bind server strictly to `127.0.0.1` (default port 4300).
4. `tests/integration/api.test.js`: Test static serving, traversal blocking, and CSRF enforcement.
Acceptance: Static files serve correctly; path traversal `../` is rejected with 403/404; server binds only to 127.0.0.1.

---

### TASK U03: Governance REST API Handlers
Implement the API endpoints in `src/server/api.js` interfacing with `repo`:
1. Endpoints:
   - `GET /api/session`: `{ csrf }`
   - `GET /api/sites`: Monitored sites list with health badge
   - `GET /api/pages?siteId=`: Monitored pages
   - `GET /api/pages/:id/snapshots`: Version list for a page
   - `GET /api/snapshots/:id`: PageSnapshot data (omit ariaYaml unless `?aria=1`)
   - `GET /api/snapshots/:id/screenshot`: Serves PNG screenshot file
   - `GET /api/changes?severity=&classification=&limit=`: Change summaries
   - `GET /api/changes/:id`: Full ChangeReport with base/head snapshot ids
   - `GET /api/repairs/:id`: RepairProposal with validation runs & oracle results
   - `GET /api/runs?limit=`: RunOutcome list
   - `GET /api/audit?entity=&id=&limit=`: Audit log entries
   - `POST /api/repairs/:id/{approve|reject|retry|rollback|resolve}`:
     Requires valid CSRF header and body `{ confirm: true, actor, reason, candidateRef? }`.
2. Wire up CLI command `healtest serve [--port 4300]`.
Acceptance: API tests pass for all endpoints; mutating endpoints reject requests lacking CSRF or confirm:true.
